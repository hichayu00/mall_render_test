# STEP 7 — 모바일·태블릿·PC 화면 정리와 직접 점검

## 1. 이번 단계의 목표

따뜻한 디자인을 유지하면서 작은 화면의 메뉴·수량 변경·긴 문구가 밀리지 않도록 CSS를 보완했습니다. 사용자가 화면 크기를 바꿔 직접 확인할 항목을 정리합니다.

**현재 상태는 코드 검토와 보완 완료, 실제 화면 확인 대기입니다.** 서버·브라우저·테스트 코드를 실행하지 않았습니다. 화면이 정상이라고 가정한 결과나 스크린샷도 만들지 않았습니다.

### 반응형은 무엇인가요?

같은 화면이 사용 가능한 가로 폭에 맞게 배치를 바꾸는 방식입니다. 예를 들어 휴대폰에서는 상품을 한 줄에 하나씩, PC에서는 세 개씩 배치합니다. 별도의 모바일 사이트를 만드는 방식은 아닙니다.

이 문서의 px는 브라우저가 레이아웃을 계산할 때 사용하는 **CSS 픽셀**입니다. 기기 화면의 물리적 해상도와 반드시 같지는 않습니다.

## 2. 변경한 파일과 코드

- 수정 파일: [static/style.css](../static/style.css)
- 생성 문서: 이 문서
- 서버 코드·DB·폼 제출 규칙은 변경하지 않았습니다.
- 패키지 설치나 SQL 실행은 필요하지 않습니다.

아래 부분을 CSS 마지막에 추가했습니다. 기존 코드는 반복하지 않습니다.

```css
/* STEP 7: 좁은 화면과 긴 내용에서 레이아웃이 밀리지 않도록 보완한다. */
.welcome-copy, .site-header nav, .history-item > div { min-width: 0; }
.hero-caption { max-width: calc(100% - 28px); }
.stock-badge { max-width: 100%; font-size: 0.8rem; }
button, .button { white-space: normal; overflow-wrap: anywhere; }
form { min-width: 0; }

@media (max-width: 599px) {
    .site-header nav { width: 100%; justify-content: flex-start; }
    .quantity-form { grid-template-columns: auto minmax(0, 1fr); }
    .quantity-form button { grid-column: 1 / -1; }
    .hero-caption { font-size: 0.75rem; }
}

/* 가로 화면이라도 높이가 짧으면 금액 영역을 고정하지 않는다. */
@media (min-width: 900px) and (max-height: 700px) {
    .order-summary { position: static; }
}
```

### 각 보완의 목적

| 변경 | 목적 |
|---|---|
| min-width: 0 | 긴 내용이 있어도 flex·grid 영역이 화면 밖으로 밀리지 않게 축소 허용 |
| 모바일 메뉴 width: 100% | 로고 아래에 메뉴를 배치해 링크가 빽빽하게 모이는 것을 완화 |
| 모바일 수량 버튼 별도 행 | 수량 입력과 저장 버튼이 좁은 한 줄을 경쟁하지 않게 함 |
| 상태 배지 크기 조정 | 품절·결제 대기 같은 글자를 조금 더 읽기 쉽게 표시 |
| 버튼 줄바꿈 | 긴 버튼 문구가 생겨도 밖으로 넘치지 않도록 함 |
| 낮은 화면에서 sticky 해제 | 높이가 짧은 창에서는 금액 영역도 일반 내용처럼 스크롤되도록 함 |

## 3. 요청 → 처리 → 응답

기존 URL 요청 → FastAPI가 기존 HTML과 데이터 응답 → 브라우저가 화면 폭·높이에 맞는 CSS 선택 → 배치 표시.

이번 단계에서는 서버의 요청 처리 흐름을 바꾸지 않았습니다. 화면 크기를 바꾸는 것만으로 주문이나 결제를 실행하지 않습니다.

### 현재 배치 규칙

| 가로 폭 | 상품 목록 | 상품 상세 | 장바구니·주문서 |
|---|---|---|---|
| 600px 미만 | 1열 | 사진 위·설명 아래 | 내용 위·합계 아래 |
| 600~767px | 2열 | 세로 배치 | 세로 배치 |
| 768~899px | 2열 | 사진·설명 나란히 | 세로 배치 |
| 900~1023px | 2열 | 나란히 | 내용·합계 나란히 |
| 1024px 이상 | 3열 | 나란히 | 내용·합계 나란히 |

900px 이상에서 금액 요약을 스크롤 중 고정하는 기존 규칙은 유지하지만, 화면 높이가 700px 이하라면 고정하지 않습니다.

## 4. 직접 실행·확인하는 방법

### ① 서버와 새 CSS 준비

서버가 실행 중이면 [상품 목록](http://127.0.0.1:8000/products)에서 **Ctrl + F5**로 새로고침합니다. 서버가 종료되어 있다면 기존 가상환경에서 실행합니다.

```powershell
python -m uvicorn app.main:app --reload
```

### ② PC 브라우저에서 작은 화면 만들기

아래는 Windows의 Microsoft Edge를 기준으로 한 방법입니다. Codex 안의 브라우저에서 개발자 도구를 찾기 어렵다면 Edge에서 같은 로컬 주소를 열어 진행하면 됩니다. 다른 브라우저로 열면 회원 로그인을 다시 해야 할 수 있습니다.

1. Edge에서 `http://127.0.0.1:8000/products`를 엽니다.
2. **F12** 또는 **Ctrl + Shift + I**로 개발자 도구를 엽니다.
3. 개발자 도구에 포커스를 둔 상태에서 **Ctrl + Shift + M**을 누르거나 휴대폰·태블릿 모양의 기기 에뮬레이션 버튼을 누릅니다.
4. 기기 목록에서 **Responsive**처럼 크기를 직접 지정하는 모드를 선택합니다.
5. 화면 위 가로·세로 크기 입력란에 아래 값을 넣습니다.

단축키와 기기 모드는 [Microsoft 공식 단축키 안내](https://learn.microsoft.com/en-us/microsoft-edge/devtools/shortcuts/)와 [기기 에뮬레이션 안내](https://learn.microsoft.com/en-us/microsoft-edge/devtools/device-mode/)를 참고했습니다. 개발자 도구의 버튼은 버전에 따라 위치나 이름이 조금 다를 수 있습니다.

| 순서 | 가로 × 세로 | 확인 목적 |
|---|---|---|
| 1 | 390 × 844 | 모바일 기본 화면 |
| 2 | 768 × 1024 | 태블릿 세로 화면 |
| 3 | 1280 × 800 | PC 화면 |
| 선택 | 320 × 568 | 더 좁은 모바일 |
| 선택 | 1280 × 600 | 높이가 짧은 창의 금액 영역 |

기기 모드가 어렵다면 브라우저 창을 좁혔다 넓히는 것부터 시작해도 됩니다. 다만 정확한 폭을 비교하려면 기기 모드가 편합니다. 실제 휴대폰에서 `127.0.0.1`을 열면 그 휴대폰 자체를 가리키므로, 이번에는 PC의 기기 모드로 확인하고 배포 후 공개 주소로 실제 휴대폰을 확인합니다.

### ③ 먼저 확인할 세 화면

**모바일 390px에서 아래 세 화면부터 확인하면 됩니다.** 새로운 주문·결제를 반복할 필요는 없습니다.

1. [상품 목록](http://127.0.0.1:8000/products): 메뉴·소개·사진·가격이 읽히고 옆으로 화면이 밀리지 않는지
2. 상품 상세: 수량 입력창과 담기·바로 구매 버튼이 화면 안에 있는지
3. [장바구니](http://127.0.0.1:8000/cart): 수량 변경 버튼이 입력란 아래에 표시되고 합계가 상품 아래에 있는지

장바구니가 비어 있다면 재고가 있는 상품 한 개를 담으면 됩니다. 실제 재고 차감은 결제 성공 시에만 이루어집니다.

### ④ 나머지 화면과 상태

아래는 **직접 확인할 체크리스트**입니다. 현재 모두 미확인 상태이며 확인한 항목에만 체크합니다.

| 화면 | 모바일 | 태블릿 | PC | 확인 포인트 |
|---|---|---|---|---|
| 상품 목록 | 미확인 | 미확인 | 미확인 | 사진·이름·가격·품절 표시, 적절한 열 수 |
| 상품 상세 | 미확인 | 미확인 | 미확인 | 사진과 설명, 입력창, 버튼 줄바꿈 |
| 로그인·가입 | 미확인 | 미확인 | 미확인 | 입력 라벨·오류 안내·버튼, 화면 밖 넘침 |
| 회원정보·수정 | 미확인 | 미확인 | 미확인 | 이메일·안내 문구, 현재·새 비밀번호 입력 구분 |
| 탈퇴 확인 | 미확인 | 미확인 | 미확인 | 동의 확인란과 안내가 잘 보이는지. 확인만 하고 제출할 필요 없음 |
| 장바구니 | 미확인 | 미확인 | 미확인 | 수량 변경·삭제, 현재 합계 위치 |
| 주문서 | 미확인 | 미확인 | 미확인 | 수령인·전화·주소 입력과 금액 영역 |
| 결제 | 미확인 | 미확인 | 미확인 | 성공·실패 버튼 구분과 안내, 금액 가독성 |
| 주문내역·상세 | 미확인 | 미확인 | 미확인 | 필터 줄바꿈, 상태·금액·배송정보·결제 기록 |

기존에 생성한 결제 대기 주문이 있으면 주문내역에서 결제 화면을 열어 배치만 확인하면 됩니다. 결제가 끝난 주문은 기존 상세와 구매내역에서 확인할 수 있습니다. 없는 상태를 보기 위해 DB 값을 임의로 바꾸거나 기존 데이터를 삭제하지 않습니다.

### ⑤ 공통 확인 포인트

- [ ] 가로 스크롤 없이 본문을 읽을 수 있음
- [ ] 긴 상품명·주소·이메일이 카드 밖으로 넘치지 않음
- [ ] 모바일에서 수량 변경 버튼이 잘리지 않음
- [ ] 버튼과 입력창이 누르기 편함
- [ ] Tab으로 이동할 때 선택한 링크·입력창·버튼의 테두리가 보임
- [ ] 브라우저 200% 확대에서도 주요 내용을 읽고 스크롤할 수 있음
- [ ] 성공·실패·품절 상태를 색뿐 아니라 문구로 구분할 수 있음

Tab 확인 중 Enter를 누르면 선택한 폼이 제출될 수 있으니, 배치 확인만 할 때는 이동과 표시만 살펴보면 됩니다. 배포 단계에서는 실제 사용 환경에서도 확인할 예정입니다.

## 5. 피드백 질문

먼저 **390px 화면에서 상품 목록·상세·장바구니**를 확인해 주세요.

- 옆으로 밀리거나 잘리는 부분이 있나요?
- 수량 입력과 변경 버튼은 편하게 보이나요?
- 태블릿·PC에서도 배치가 자연스러운가요?

문제가 있다면 **어느 화면인지, 가로 폭이 몇 px인지, 무엇이 잘리는지** 알려주세요. 스크린샷을 보내셔도 되지만 이름·주소 등 개인정보는 가려 주세요.

직접 확인 결과를 받은 뒤 필요한 부분을 보완하고 STEP 8 Render 배포 설정으로 진행합니다.
